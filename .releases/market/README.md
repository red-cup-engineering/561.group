# Existing Market release carrier

This directory adds only the Market-specific receiver and native runner fabrication seam to the Group's existing private carrier and Cloudflare credential lane. Play, the Group site, Koios, static application publishers and other targets are unchanged.

After the original Market artifact and original receiver have been qualified, or when an exact native fabrication work order is selected for the public runner, the reviewed Group source selects an actual carrier with `selection.json`:

| Key | Value |
|---|---|
| `kind` | `561.market-worker-carrier-selection/v1` |
| `repository` | `561-group/561-group-frontdoor-services-section` |
| `revision` | The actual immutable carrier commit |
| `directory` | One directory under `.service-releases/market/` |
| `manifestSha256` | SHA-256 of the exact original Market `manifest.json` |
| `operation` | Optional `observe` or `release`; omission retains `release` |
| `workOrder` | Optional `.releases/market/work-order.json` selecting native runner fabrication |
| `workOrderSha256` | Required when `workOrder` is present; SHA-256 of the exact `work-order.json` |

There is deliberately no fabricated selection file. Without a real selected artifact, source checks report that no provider access is selected. A dispatch cannot supply an unreviewed alternative repository, path, artifact digest or target.

`deploy-market.yml` uses the established `SITE_CONTENT_DEPLOY_KEY` to read that pinned private carrier and the established `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN` only in its selected-operation step. The Group transport checks every file before executing the original Market receiver. A preceding uncredentialled step invokes the receiver's actual `--verify` path for that same operation. Source, version, byte, binding, merchant, promotion and rollback policy remain the original Market and Cloudflare owners.

When `selection.json` also binds `workOrder` and `workOrderSha256` (`kind: 561.market-worker-fabrication-work-order/v1`), the uncredentialled `receive` step first restores and verifies the pinned incumbent Frontdoor carrier and its incumbent declarations, then checks out the pinned private `red-cup-engineering/market.561.group` and `causeway-services/public-market-services-section` sources into an isolated `0700` ephemeral workspace using dedicated source-owner deploy keys (`MARKET_SOURCE_DEPLOY_KEY` and `MARKET_PARAMETERS_DEPLOY_KEY`). It verifies canonical Git origins, commits, trees, the `parameters` submodule gitlink, every declared repository source input and qualification suite digest, `.npmrc` credential-free registry configuration, and `pnpm-lock.yaml` supplier SRI hashes before installing the frozen supplier closure (Corepack explicitly selects the work-order `pnpm@<version>`, receives its effective `--version` before `install --frozen-lockfile --ignore-scripts`, and records that command/version in the fabrication receipt). It verifies the installed `wrangler`, `esbuild` and `workerd` compiler closure and supplier manifests/file bytes inside the contained checkout, invokes the original Market native producer (`buildNativeMarketWorker`), native qualification receiver (`receiveNativeMarketWorker`) and release-receiver builder (`buildMarketWorkerReleaseReceiver`), assembles the fifteen-file native carrier, disposes the ephemeral private source and dependency workspace, and records `fabrication-receipt.json` before `verify` and the selected `observe` or `release` operation run. Private child diagnostics are captured rather than inherited by the public CLI. Failures emit only `MARKET_OPERATION_FAILED`; bounded diagnostics stay in a private `0700` runner directory with a `0600` file, and the always-run cleanup disposes them before the receipt-only artifact upload.

An explicit `observe` selection dispatches the original Market receiver's `--observe` mode through this same lane. It only reads current provider deployment/latest/configuration and exact selected version bytes; it does not upload, deploy, change settings or publish a directory listing. The existing receiver separately admits an attempted prior operation as observation evidence while preserving ordinary release's zero-traffic gate. Before either credentialled command, the Group rereads its original selection and requires both the exact manifest (or verified `fabrication-receipt.json` for a selected work order) and operation to match. An observation selection therefore cannot dispatch release. A later source/selection commit can choose the appropriate next operation after the actual observation has been received, without adding another workflow.

The observation artifact has kind `561.market-worker-provider-observation/v1`. Completion records what the original provider actually returned; its `providerCustodyReceived` comparison may remain false. It does not establish public catalog/payment receiving or authorize release. Current public incarnation, provider custody, deployment execution and economic outcome remain separate observations.

The native producer's carrier contains fifteen exact files: seven common artifacts and eight source-custody artifacts, including its original `parameterSourceManifest`. The original Market receiver checks that manifest's bytes and its declared Public Git binding against the selected Public edition. The older retained-producer carrier remains seven files. An incomplete fourteen-file native carrier is refused instead of dropping the Parameters source custody.

For recovery of an already staged version, the Market owner can select one additional `priorReleaseReceipt` artifact, bounded to 128 KiB and received by the same exact length/hash/path rules. This produces sixteen native files or eight retained-producer files. An unrelated extra artifact is not admitted as a recovery receipt. The Group transports that original receipt; the original Market receiver owns its meaning, unchanged-traffic proof, live baseline agreement, exact staged-byte receiving and promotion/rollback decisions. The manifest may separately pin the original receiver's source commit while preserving the Worker's original source, build and native execution evidence.

Large artifacts may travel as standard gzip files named exactly `<selected-path>.gz` in the same pinned carrier. The original manifest, uncompressed digests, source editions and fifteen-file closure remain unchanged. The explicit `receive` command restores only missing raw files before the existing read-only `verify` command. It bounds compressed input to 16 MiB, bounds native decompression to the exact selected output length, checks that length and SHA-256, and writes exclusively through a contained non-symlink parent. Existing raw files must already match and are never replaced by their compressed siblings. Malformed, truncated, oversized, escaping or altered material is refused; there is no archive extraction or new transport index. Both receiving and verification run before the workflow exposes Cloudflare credentials.

The ephemeral carrier and fabrication directories are disposed before workflow completion, and only the original Market `receipt.json` is retained as a workflow artifact. It is not a settlement receipt or a customer-paid revenue claim. No credential values, private source closures, built Worker bundles, provider error bodies or secret values are printed or retained.
